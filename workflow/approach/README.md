# workflow/approach/

Demand-evidence hunt plans from the `pain-hunt` skill. Each file lays out where to find people *already complaining* about the problem in their own words — Reddit, Twitter/X, HN, niche Discords, G2/Capterra reviews of adjacent products, YouTube comments, trade forums, in person — plus an interview script that avoids leading questions.

Hypothetical "would you use it?" answers don't count. Only unsolicited pain does.

## File format

`#NNNN-<slug>.md`. Counter is per-folder; the slug usually matches `../ideas/` and `../marketing/` when run in order. Re-running appends a new dated section; the number stays fixed.

## Template

```
# Demand Evidence Plan — <idea>

**Complaint phrasing:** "<words a real sufferer would actually use>"
**Region / language:** ...
**Audience:** online-native / traditional / mixed
**Adjacent products to mine:** ...

## Where to hunt (online)
## Where to hunt (traditional, if applicable)
## Client interview script (aim for 5–7)
## Survey (only after interviews refine the questions)
## What to log per signal
## Kill criteria
```

## Kill criteria for the hunt itself

Fewer than ~5 unsolicited complaints after a serious hunt — or all evidence is mild ("would be nice") rather than acute — is a signal to kill or pivot, not push past.
